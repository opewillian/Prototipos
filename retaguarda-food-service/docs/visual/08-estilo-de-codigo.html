Estilo de código

JavaScript

Fazer

  • Um arquivo por módulo em src/modules/<área>/, exportando render(ctx).
  • Peças comuns em src/core/ e src/modules/shared/; não copiar código entre Matriz e Loja.
  • Dados só por db.js (ou supabase.rpc / função degust).
  • HTML montado como texto, sempre passando dado do usuário por e().
  • Números e datas por format.js (money, num, dateBR, parseNum).
  • Depois de cada await, conferir ctx.isCurrent() antes de desenhar.
  • Buscas independentes em paralelo com Promise.all.
  • Comentário curto no topo do arquivo dizendo o que a tela faz e as regras que ela segue.

Evitar

  • Framework, bundler ou dependência nova sem decisão.
  • Cálculo de regra de negócio espalhado por componentes.
  • window.confirm e alert: usar confirmDialog e toast.
  • localStorage para dados (só preferências de tela, ex.: rfs-last-route).
  • Ler tabela grande sem ordem única.
  • Reescrever arquivo inteiro quando uma mudança localizada resolve.
Formatação

Aspas duplas, ponto e vírgula, indentação de 1 espaço, linhas compactas. Seguir o estilo do arquivo que está sendo editado.

Nomes

Código em inglês curto (render, loadItems, drawYear); textos de tela e comentários em português.

Atributos de evento

Ações ligadas por data-* (data-new, data-print-form, data-yrm) e querySelector dentro de ctx.el.

Modelo de módulo

// Loja · Perdas: validade, quebra, avaria e descarte. Registrar reduz o estoque (gatilho do banco).
import {list} from "../../core/db.js";
import {e,money,dateBR} from "../../core/format.js";
import {pageHead,btn,dataTable,card,emptyState} from "../../core/ui.js";

export async function render(ctx){
 if(ctx.params[0])return detail(ctx,ctx.params[0]);          // rota com id = tela de detalhe
 const rows=await list("losses",{eq:{store_id:ctx.storeId},  // sempre no escopo da loja
  order:"loss_date",order2:"created_at"});
 if(!ctx.isCurrent())return;                                 // usuário já saiu da tela
 ctx.el.innerHTML=pageHead("Perdas","Registro de perdas com baixa no estoque.",
   btn("Registrar perda",{icon:"plus",attrs:"data-new"}))+
  card("",rows.length?dataTable([...],rows):emptyState("Nenhuma perda registrada."));
 ctx.el.querySelector("[data-new]").onclick=()=>{ /* cria o rascunho e abre */ };
}

CSS

Onde

  • assets/app.css: tokens e componentes.
  • assets/shell.css: login, menu e barra superior.
  • Regras novas ao fim do arquivo, com comentário /* Tela › parte */.

Como

  • Cores sempre por token (var(--brand)), nunca hex solto para cores da marca.
  • Prefixo curto por tela: pm- (painel da Matriz), rc- (recibos), lc- (gráfico de linha).
  • white-space:nowrap em tabelas; rolagem horizontal em vez de quebrar.
  • Respeitar prefers-reduced-motion em animações.

-- 53: sales_by_month passa a trazer também os cupons, 24/11/2026.
-- Pedido: no gráfico mês a mês do Painel da Matriz, trocar
-- entre Faturamento e Cupons, com comparativo do ano anterior.
begin;
drop function if exists public.sales_by_month(date, date);
create function public.sales_by_month(p_from date, p_to date)
returns table (month date, net numeric, cupons bigint,
               days integer, stores integer)
language sql stable security invoker set search_path = '' as $$
  select ... from public.sales_imports i ...
$$;
revoke all on function public.sales_by_month(date, date) from public, anon;
grant execute on function public.sales_by_month(date, date) to authenticated;
select * from public.sales_by_month('2025-09-01', '2026-11-23');
commit;

Regras

  • Arquivo docs/sql/NN-descricao-curta.sql, número seguinte ao último.
  • Cabeçalho: número, o que muda, data e o pedido do usuário.
  • Tudo entre begin e commit, com um select de conferência.
  • Funções com set search_path = '' e nomes com esquema (public.).
  • Preferir security invoker; security definer só com motivo escrito.
  • revoke de public/anon e grant só a authenticated.
  • Toda tabela nova com RLS e políticas no mesmo script.
